Time Tracker — User Guide

How to use the tt CLI day to day · updated 2026-06-29

The one-line mental model: your meetings (from Google Calendar) are a fixed scaffold; tt helps you capture and understand the gaps between them. Everything you log lands on a single daily timeline you can review and report on.

Does it work from anywhere?

Yes. A global launcher is installed at ~/.local/bin/tt, which is on your PATH. Open any new terminal, in any folder, and just run:

tt in

You do not need to cd into the project folder, and you do not need to run conda activate time_tracker first — the launcher points straight at the right Python environment. Your data is stored centrally (see Where your data lives), so the working directory never matters.

The conda activate time_tracker step is only needed for development (editing the code, running pytest) — not for everyday use.

Command reference

CommandWhat it does
tt inClock in for the day (records your real arrival time — you're often in before your first meeting).
tt outClock out for the day.
tt startStart a live timer. With no flags, prompts interactively for category and description (shows your existing values as a pick list). Flags: -c category, -d description, --at HH:MM to backdate the start. Errors immediately if a timer is already running.
tt stopStop the running timer and log the elapsed span.
tt checkinLog what you've been doing since your last activity. With no args, prompts for description and category. Or: tt checkin "emails" -c admin.
tt log START ENDRetrospectively log a past block at any time of day, e.g. tt log 09:30 10:30 "wrote spec" at 3pm. Times are HH:MM local (or full ISO). Omit description/category to be prompted. --date 2026-06-26 for another day.
tt edit [--date]Pick a logged entry from today (or --date) and edit its start, end, description, or category interactively.
tt delete [--date]Pick a logged entry and delete it after confirmation.
tt recat OLD [NEW]Recategorize entries. tt recat "MATS chats" "MATS workplace" bulk-renames every entry. With just tt recat "MATS chats", pick which of that category's entries to move elsewhere — e.g. splitting "fellows" out of a broader chat category.
tt day [date]Show the day's timeline: meetings, logged entries, and open gaps. Defaults to today.
tt sync [--days N]Pull meetings from Google Calendar (±N days, default 7). Meetings are auto-tagged with a category if their title matches a rule in meeting_category_rules (see below).
tt meeting [--date]Pick a meeting from a day and set its category by hand. This manual choice is an override — tt sync will never overwrite it, even if a title rule would say otherwise.
tt report [week|day]Render an offline HTML report — a matplotlib time-by-category bar chart, a per-day meetings/focus/idle breakdown, and the by-day table (categorized meetings folded into the totals) — to ~/.time_tracker/reports/ and open it in your browser. Defaults to the week; pass day for just today. Add --text for a quick terminal-only summary instead (handy over SSH / when piping). Where a logged entry overlaps a meeting, the entry wins — that time counts once, under the entry's category — so totals never double-count.
tt install-remindersSet up macOS notifications (daily clock-in + periodic check-in).
tt uninstall-remindersRemove those notifications.
tt --helpList all commands; tt <command> --help for details on one.
Shortcuts. Any command taking a date accepts today, yesterday, tomorrow, or a signed day offset like -1 in place of an ISO date — e.g. tt day yesterday, tt log 09:00 10:00 "x" --date -1. There are also terse aliases for the commands you type most: td → tt day, tl → tt log, ci → tt checkin, rc → tt recat.

A typical day

# Morning — when you actually sit down (before any meetings)
tt in

# Pull today's meetings (or rely on the synced cache)
tt sync

# Starting a focused block — tt start with no flags prompts you interactively.
# Arrow keys to pick a category from your history (or "New…" to create one).
tt start
# ...work...
tt stop

# Quick flag version if you already know what to log
tt start -c dev -p tracker -d "refactor sync logic"

# Came back from a meeting / a scattered hour — log it after the fact
tt checkin "answered emails, reviewed two PRs"

# Glance at the day so far — what's tracked, what's an open gap
tt day

# End of day
tt out
tt report day      # where did today actually go?
tt report week     # zoom out: trends, fragmentation, categories

The aim isn't to track every second — it's to get an honest-enough picture. Clock in/out frame the day, meetings come in automatically, and you fill the gaps with whichever capture style suits the moment.

The three ways to capture time

All three write to the same timeline; mix and match freely.

ModeUse when…How
Live timerYou're starting a focused block and want an accurate measure.tt start … then tt stop
Check-inYou forgot to start a timer, or want quick periodic sampling. Logs from your last activity to now.tt checkin "what you did"
Retrospective logReconstructing the day afterwards. Look at the gaps in tt day and fill them in.tt log 09:30 10:30 "deep work"

Editing and deleting entries

Made a mistake, or tagged something with the wrong category?

CommandWhat happens
tt editShows a pick list of today's completed entries. Select one, then press Enter to keep each field or type to replace it (time, description, category).
tt edit --date 2026-06-26Same, but from a past day.
tt deletePick an entry, confirm with y/N.
tt delete --date 2026-06-26Delete from a past day.
Both commands require an interactive terminal (they use arrow-key menus) — they won't run in a pipe or script.

Connecting Google Calendar

Meetings appear automatically once you've connected your calendar (one-time setup):

  1. In the Google Cloud Console, create a project and enable the Google Calendar API.
  2. Configure the OAuth consent screen (External; add your own email as a test user).
  3. Create an OAuth Client ID of type Desktop app and download credentials.json.
  4. Place it at ~/.time_tracker/credentials.json.
  5. Run tt sync — a browser opens for consent once; the token is cached and auto-refreshes afterwards.
Noise is filtered out by default. Two types of Google Calendar entries are excluded from your day view and gap calculations:
  • Pink reminders (Google colour-4 "Flamingo") — change via excluded_color_ids in config.toml.
  • Working location markers ("Office", "Home" etc.) and Focus Time blocks — change via excluded_event_types in config.toml.
Auto-categorizing meetings. Add rules to ~/.time_tracker/config.toml and every synced meeting is tagged automatically. Each rule matches on a Google Calendar color (its colorId), a title match substring, and/or attendee count (min_attendees / max_attendees); rules are tried in order and the first match wins. A rule with no matchers (just a category) is a catch-all — put it last, or omit it to leave unmatched meetings untagged. 
meeting_category_rules = [
  { color = "3",  category = "Fellow 1:1s" },
  { color = "6",  category = "Non-fellow meetings" },
  { color = "10", category = "Stream meetings" },
  { color = "8",  category = "Social" },
  { color = "11", category = "Personal" },
  { min_attendees = 3, category = "Team meetings" },  # multi-person, any colour left over
]
Colour is the primary signal; add a { match = "…", category = "…" } rule above the colour rules to carve a title-based exception out of a colour, and use min_attendees to split big team meetings from 1-2 person ones. Need to fix a single meeting? tt meeting sets a manual category that tt sync will never overwrite.

Reminder notifications

Run tt install-reminders once to get macOS banners:

  • A daily clock-in nudge at your configured time (default 09:00) — handy since you're often in before your first meeting.
  • A periodic check-in nudge (default every 45 min) prompting tt checkin.

Tune the times in ~/.time_tracker/config.toml (clock_in_reminder_time, checkin_interval_minutes — set to 0 to disable check-ins), then re-run tt install-reminders. Remove everything with tt uninstall-reminders.

Where your data lives

FileContents
~/.time_tracker/tracker.dbYour SQLite timeline (all entries, meetings, workdays).
~/.time_tracker/config.tomlSettings: reminder times, excluded colours, work-hours window.
~/.time_tracker/credentials.jsonYour Google OAuth client (you provide this).
~/.time_tracker/token.jsonCached calendar access token (auto-created).

Because everything is under your home folder, the data is the same no matter which directory you run tt from. Back up tracker.db to keep your history.

Good to know / gotchas

One timer at a time. tt start checks immediately (before any prompts) and errors if a timer is already running — tt stop first.
Time zones: day boundaries and the work-hours window are computed in your local time. Times you type into tt log are local too.
Reports need a framed day. Idle/focus/meeting splits use your clock in/out window. If you never clock in, tt infers the window from your first/last activity, but clocking in gives the truest picture.
